🧭 Diagrama de Blocos do Algoritmo In-Place

1. INÍCIO: resolver_caso(n, max_pizzas, pedidos)
Aloca vetor 1D: dp = [0] * (max_pizzas + 1) (Memória: O(P))
▼
2. LAÇO EXTERNO: para cada (tempo, pizzas) em pedidos
Analisa cada pedido individualmente (de i = 1 até N).
▼
3. LAÇO INTERNO: w de max_pizzas descendo até pizzas
★ PONTO CRÍTICO: Varredura DECRESCENTE (Direita ➔ Esquerda)
Garante que o pedido seja considerado no máximo 1 vez (0-1)!
▼
4. NÓ DE DECISÃO DE BELLMAN:
if dp[w - pizzas] + tempo > dp[w]:
[SIM: LEVAR O PEDIDO]
dp[w] = dp[w - pizzas] + tempo
Ganha o tempo e ocupa pizzas
[NÃO: MANTER ANTERIOR]
dp[w] permanece inalterado
Decisão prévia já é melhor
▼
5. DECREMENTO: w = w - 1
Continua até w atingir (pizzas - 1). Em seguida, próximo pedido!
▼
6. RETORNO ÓTIMO: return dp[max_pizzas]
Valor ótimo global final no índice máximo da capacidade!

💻 Código Fonte e Racional Matemático

def resolver_caso(n, max_pizzas, pedidos):
    # Vetor unidimensional compacto (O(P))
    dp = [0] * (max_pizzas + 1)
    
    for tempo, pizzas in pedidos:
        # Varredura decrescente (preserva 0-1)
        for w in range(max_pizzas, pizzas - 1, -1):
            if dp[w - pizzas] + tempo > dp[w]:
                dp[w] = dp[w - pizzas] + tempo
                
    return dp[max_pizzas]

❓ Por que a Varredura DEVE ser Decrescente?

Se varrêssemos para frente (w = pizzas ... max_pizzas):

❌ Erro da Mochila Ilimitada:
Em w = 2, calcularia dp[2] = 20.
Em w = 4, consultaria dp[4-2] = dp[2] (que já virou 20 nesta rodada) e somaria de novo: 20 + 20 = 40! O mesmo pedido seria multiplicado!

Ao varrer para trás (w = max_pizzas ... pizzas):

✅ Rigor da Mochila 0-1:
Ao atualizar dp[w], o valor em dp[w - pizzas] ainda é do estágio anterior (i-1), garantindo que cada pedido seja adicionado no máximo 1 vez!
